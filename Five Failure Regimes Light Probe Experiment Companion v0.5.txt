Vocabulary and Type Firewall
The scientific protocol and the Lean adapter use several vocabularies that may look similar while performing different jobs. They must not be collapsed into one another.
Universal Contract Vocabulary
Disposition.discharged
A declared contract burden has been positively satisfied under the supplied evidence relation.
Disposition.violated
A declared contract burden has been positively failed under the supplied evidence relation.
Disposition.open
The burden remains unresolved or otherwise not closed for the requested machine route.
These are contract-status terms. They are not automatically synonyms for experimental PASS, FAIL, or UNRESOLVED.
Route-Condition Vocabulary
ConditionStatus.pass
The registered scientific test for that live condition passed.
ConditionStatus.fail
The registered scientific test for that live condition failed.
ConditionStatus.notLive
The registered physical route does not require that condition.
NOT-LIVE is not PASS and is not FAIL.
ConditionStatus.unresolved
The condition is relevant, but the available intrinsic information cannot adjudicate it reliably enough for the requested classification.
UNRESOLVED is not PASS and is not FAIL.
J_ROUTE Vocabulary
JRouteStatus.pass
The registered physical route performed the task for which it was registered.
JRouteStatus.fail
The registered physical route did not perform that task under the frozen domain-native criterion.
JRouteStatus.unresolved
The registered criterion cannot adjudicate the route state reliably enough.
A J_ROUTE failure is necessary for a named route failure or structural-residual route, but J_ROUTE FAIL alone does not identify a Failure Regime.

Scientific Record → Machine Population Ledger
Purpose
This ledger states where machine values come from.
It never supplies those values.
The governing rule is simple:
Scientific authority adjudicates the state.
The execution record preserves that adjudication.
The adapter receives the adjudicated state.
Lean checks what follows from it.
A machine field must therefore never be populated merely because a particular value makes a theorem easier to prove.
For each machine destination, the operator should be able to identify six things:
Machine destination — the exact adapter field or burden family.
Scientific owner / source — the anchor-owned record or domain adjudication that supplies the value.
Population time — when that value is fixed or adjudicated.
Forbidden source — information that may not lawfully be used to populate it.
Open / unresolved behavior — whether a non-final state is permitted and what that state means.
Claim consequence — what the populated value can constrain or license.

Route / First-Break Machine Interface
Operator Purpose
The route / first-break interface is the first machine seat at which the scientific execution can ask Lean for a named Failure-Regime certificate.
The machine does not:
* discover the route;
* choose the physical object;
* decide the primary scale;
* or infer condition states from a probe image.
Those facts must already exist in the frozen scientific record.
The operator’s task is therefore translation without reinterpretation:
1. identify the already-warranted physical object, route, and scale;
2. populate the route record from the frozen intrinsic scientific adjudication;
3. populate and warrant the entry burdens;
4. preserve the four-state condition vocabulary exactly;
5. request only the machine proposition actually licensed by that record.
Build the Route Contract Before Asking for a Class
A valid route packet has two parts.
RouteRecord
This contains:
* object;
* route;
* scale;
* E / produced;
* J_ROUTE;
* and G = (P₀, Pₗ, B, C, A).
Contract
This contains the RouteRecord plus the pre-outcome EntryBurden dispositions and their evidence / warrant relation.
EntryReady means every required EntryBurden is:
Disposition.discharged
An entry burden that is:
Disposition.open
or:
Disposition.violated
blocks the confirmatory first-break route.
The operator must return to the anchor-owned record rather than insert a favorable disposition merely to make a proof go through.
The entry surface is deliberately broader than the five condition tests. It includes:
* physical-candidate warrant;
* mechanism admission;
* participation-relation pinning;
* minimum-admissible-route status;
* frozen primary-scale ownership;
* frozen J_ROUTE;
* frozen capacity tests;
* the intrinsic-input boundary;
* held-out-probe exclusion;
* and intact pre-target freeze.
A clean G vector cannot compensate for a broken entry surface.
Preserve the Four-State G Vector
ConditionStatus.pass, fail, notLive, and unresolved are scientific states supplied by the frozen route adjudication.
They are not alternative spellings for Boolean true and false.
The operator must preserve three distinctions.
NOT-LIVE
The registered route does not require the condition.
UNRESOLVED
The condition is relevant, but it cannot be adjudicated to the required reliability.
FAIL
The live registered test positively failed.
RegistrationConsistent requires both scientific prerequisite consistency and prerequisite-closed liveness.
In practical terms:
* a downstream condition cannot remain live after a structurally required predecessor has been declared NOT-LIVE;
* and a later PASS cannot erase an earlier live FAIL.
An inconsistent record is not converted into the nearest regime.
It is an inadmissible confirmatory input until the scientific registration problem is repaired under the anchor’s amendment rules.
J_ROUTE Is a Separate Gate
J_ROUTE answers whether the registered physical route performed its domain-native task.
It is not itself the first-break classifier.
The machine therefore distinguishes:
JRouteStatus.pass — the route succeeded under the frozen physical criterion.
JRouteStatus.fail — the route failed and may be eligible for a named first break or later residual analysis.
JRouteStatus.unresolved — the route-success criterion itself is not adjudicated.
LicensedFirstBreak requires:
J_ROUTE = FAIL
A route with J_ROUTE = PASS or UNRESOLVED cannot receive a named first-break license merely because one field of G has an attractive pattern.
LicensedFirstBreak
LicensedFirstBreak is the route-level machine proposition for a named class.
It requires all of the following:
* EntryReady;
* J_ROUTE = FAIL;
* RegistrationConsistent G;
* FirstBreakEvidence for the requested class.
FirstBreakEvidence is prefix-sensitive.
The requested break condition must FAIL, and every class-defining predecessor must PASS.
Later conditions do not redefine an earlier first break.
The five machine class patterns mirror the anchor’s scientific decision matrix:
Dissolution — E present; P₀ FAIL.
Shear — E present; P₀ PASS; Pₗ FAIL.
Drift — E present; P₀ PASS; Pₗ PASS; B FAIL.
Echo — E present; P₀ PASS; Pₗ PASS; B PASS; C FAIL.
Lock — E present; P₀ PASS; Pₗ PASS; B PASS; C PASS; A FAIL.
NOT-LIVE or UNRESOLVED at a condition required for the requested class blocks that class.
A failed predecessor blocks every later class that presupposes its success.
PrimaryConfirmatoryFirstBreak
PrimaryConfirmatoryFirstBreak adds one burden to LicensedFirstBreak:
the record must own:
ScaleRole.primary
This distinction matters because the anchor permits scientifically useful secondary diagnostic scales while reserving the confirmatory first-break and closure result for the pre-registered R_PRIMARY seat.
A FirstBreakCertificate on a secondary scale can still encode a scoped route-level result.
But it is not a PrimaryFirstBreakCertificate, and it cannot replace the frozen primary result after target access.
PASS Control Is Not Depth 5 in Every Case
RoutePassControl is the domain-level non-failure control.
It requires:
* J_ROUTE = PASS;
* RegistrationConsistent G;
* no physically live foundational condition FAILS.
LicensedRoutePassControl adds the clean EntryReady surface.
This is intentionally broader than the kernel’s fully-live depth-5 projection.
A route may be a valid PASS control while one or more downstream conditions are legitimately NOT-LIVE.
Such a record is not forced into the fully-live Boolean-depth interface.
AllFivePass and kernel depth 5 are used only where all five conditions are:
* fully live;
* resolved;
* and PASS.
The operator must not use depth 5 as a generic synonym for every scientific PASS control.
RouteFailureWithoutKnownBreak Is Only a Handoff Surface
RouteFailureWithoutKnownBreak means:
* J_ROUTE = FAIL;
* the registered G vector is consistent;
* no physically live known foundational condition FAILS.
This state is intentionally not named SRW.
It contains no claim that:
* the ordinary model library has been cleared;
* the mixture model has been cleared;
* the measurement pipeline has been cleared;
* the novelty threshold has been crossed;
* replication has succeeded;
* or the state-completeness ladder has been exhausted.
The correct operator interpretation is:
the route failed and the known live first-break tests did not classify that failure at this stage.
The next permitted machine action is a residual audit only after the relevant branch and ordinary-explanation gates are satisfied.
The operator must not report:
* SRW;
* closure suspension;
* or FR₆
from this route-level handoff alone.
KernelCompatible Is a Relation, Not a Coercion
The Universal Kernel represents foundational capacities propositionally.
The experiment represents P₀, Pₗ, B, C, and A using four scientific states.
The adapter therefore uses KernelCompatible to relate the two representations without erasing scientific information.
Under ConditionCompatible:
PASS constrains the corresponding kernel proposition to hold.
FAIL constrains the corresponding kernel proposition not to hold.
NOT-LIVE imposes no Boolean truth-value claim.
UNRESOLVED imposes no Boolean truth-value claim.
A kernel-compatible snapshot must therefore not be read backward as though Lean had adjudicated a NOT-LIVE or UNRESOLVED scientific condition.
For fully live, resolved records, resolvedKernelProjection supplies the narrower Boolean projection used for firstBreakDepth.
That projection is not the general route-record representation.
Named FirstBreakEvidence maps into one of the Universal Kernel’s already-existing five FailureClosure regimes.

ClosureEffect Firewall
The branch layer intentionally has only three closure effects:

* untestedByBranch;

The firewall prevents two opposite mistakes:
* a lower-level failure being exaggerated into foundational novelty;

Certificate Interpretation
General Rule
A machine certificate is a typed proof carrier for one encoded conditional consequence.
It must always be interpreted together with:
* the exact populated execution record;
* the scientific evidence that supplied that record;
* the scope and identity of the route, branch, residual, or program object;
* and the claim ceiling owned by the scientific anchor.
A machine-clean certificate does not validate incorrectly populated empirical premises.
For every certificate, the operator should ask four questions.
What exact record is this certificate bound to?
What proposition does it prove?
Is the certificate diagnostic, or is it the final reportable machine state?
What scientific statement does the anchor license from that proposition?
The certificate never answers the fourth question by itself.

That remains true even when the result is U₁ EARNED.

The absence of a requested certificate has no single scientific meaning.

* an open scientific burden;
* a violated burden;
* malformed or inconsistent population;
* a requested claim stronger than the record supports;
* use of the wrong machine route;
* a scientific state that is intentionally anchor-owned rather than represented as a Lean conclusion;
* or a formal engineering defect.
The operator must diagnose which case applies before drawing any scientific conclusion.
No proof does not automatically mean scientific failure.
Likewise, inability to obtain one strong certificate may coexist with a narrower valid scientific result.
Machine-Coverage Boundary
The adapter intentionally does not duplicate every anchor-owned scientific state as a theorem constructor.
Examples of states that may remain primarily in the scientific execution record include:
* DCR provenance;
* known-mixture states;
* purity states;
* coalescence states;
* underpowered calibration states;
* some freeze and execution records;

Its purpose is to formalize claim transitions and firewalls where formal enforcement is useful—not to reproduce the entire scientific taxonomy for symmetry.
This boundary remains acceptable only while an omitted state cannot create a machine-significant shortcut.
If a later audit shows that an omitted scientific distinction must become machine-visible in order to preserve a claim boundary, that finding creates adapter pressure.
Until then, the scientific anchor remains authoritative over those states.

Firewalls and Forbidden Shortcuts
The released adapter is designed to prevent or expose the following invalid moves.
1. NOT-LIVE treated as FAIL.
A condition that the registered route does not require is not a failed condition.
2. NOT-LIVE treated as PASS.
Lack of liveness does not constitute successful performance of the condition.
3. UNRESOLVED treated as FAIL.
Insufficient adjudication is not positive failure.
4. UNRESOLVED treated as PASS.
Insufficient adjudication is not positive success.
5. Downstream liveness bypassing a NOT-LIVE predecessor.
A later structural condition cannot remain live when its required predecessor has been declared not live.
6. A later failure overriding first-break prerequisite order.
The first live failure owns the first-break classification. A later failure does not replace it.
7. J_ROUTE FAIL treated as a named first break without class evidence.
Route failure is necessary for a named first break, but is not sufficient.
8. PASS treated as a sixth Failure Regime.
PASS is the non-failure control state, not an additional failure class.
9. A secondary scale replacing the primary confirmatory result after target access.
Secondary scales remain diagnostic unless prospectively registered as primary in a later execution.
10. Morphology or held-out probe evidence used to manufacture intrinsic class assignment.
Failure-Regime classification must remain upstream of the probe result used to test it.
11. SEARCH FAILURE treated as evidence against the branch prediction itself.
Failure to place the branch under pressure is not failure of the branch hypothesis.
12. PHYSICALIZATION, SOURCE, LIGHT, MEASUREMENT, or O₂ failure treated as foundational novelty.
Each failure remains at the narrowest layer actually contradicted.
13. U₁ EARNED treated as proof that five-regime closure survived.
Incremental predictive utility and foundational closure answer different questions.
14. Novel observable pressure promoted directly to SRW.
Rᵤ > εᵤ opens novelty pressure, not a structural residual witness.
15. SRW entered without the full RouteUnknownHandoff.
The route must preserve:
clean branch setup + adequate search + valid entry / registration + primary scale + E + route failure + no known first break
before SRW entry is licensed.
16. SRW promoted directly to FR₆.
The replication, state-completeness, suspension, candidate, and newness burdens cannot be skipped.
17. An unreplicated SRW suspending closure.
One structural residual witness is insufficient for foundational suspension.
18. An incomplete state-completeness ladder suspending closure.
Closure suspension requires the pre-frozen ordinary-state ladder to have been exhausted.
19. Richer-state resolution ignored in order to preserve novelty.
If a richer admitted ordinary state resolves the witness, the correct result is state-incompleteness resolution.
20. Candidate rejection treated automatically as witness resolution.
A failed K* candidate can leave the underlying residual completely unresolved.
21. Known-capacity reduction treated as closure restoration without scientific confirmation that the witness was actually resolved.
Reduction alone does not restore closure.
The residual itself must be accounted for.
22. Intervention unavailability used as a post-hoc waiver.
Intervention availability must be adjudicated under the predeclared rule, not invoked opportunistically after the result.
23. Reduction to a known capacity ignored because the candidate has a new name.
Terminological novelty does not establish structural novelty.
24. Functional equivalence ignored because the parameterization differs.
A changed mathematical or descriptive representation does not create a new structural job if the candidate is functionally equivalent to known structure.
25. A diagnostic ResidualMilestoneCertificate used to under-report an active stronger final residual state.
Milestones preserve history.
They do not override the strongest supported final report.
26. CLOSURE SUSPENDED reported as closure survived.
Suspension is an active restriction on a survival claim.
27. reopenedAtTestedScope reported as closure survived.
Reopening is not survival.
28. An unresolved or untested branch assigned an invented first-break class instead of none.
Missing class information must remain missing.
29. An unresolved or untested branch assigned an invented closure status instead of none.
No closure result is not equivalent to unchanged.
30. A closure-survival claim made where the foundational closure test was never actually placed under pressure.
Ordinary branch testing is not automatically foundational testing.
31. A provisional or unfinalized closure status used in a final program survival claim.
Program closure reporting requires finalized status.
32. A missing registered branch silently dropped from the final program record.
Complete accounting includes adverse, unresolved, and untested registered branches.
33. Successful branches selected after target access to manufacture a cross-regime U₁ claim.
The support set is frozen prospectively.
Later success cannot rewrite it.
34. Incompatible branches averaged into one global score.
Branch validity does not imply compatibility for one aggregate claim.
35. U₁ aggregation used to override foundational closure status.
Predictive utility cannot erase a suspended or reopened foundational state.
36. Lean elaboration success treated as empirical validation.
A clean compile establishes that the encoded formal object elaborates and the proofs check.
It does not establish that the scientific premises are true of nature.
Firewall Compression
The entire firewall set can be compressed into five operator rules.
Preserve scientific state distinctions exactly.
PASS, FAIL, NOT-LIVE, UNRESOLVED, OPEN, VIOLATED, and DISCHARGED perform different jobs.
Preserve causal and adjudicative order.
Do not let downstream observations rewrite upstream registration, classification, or freeze state.
Escalate only through the licensed handoff.
Ordinary failure does not become structural novelty, novelty does not become SRW, SRW does not become suspension, and suspension does not become FR₆ without the intervening burdens.
Preserve negative and unresolved evidence.
Do not invent classes, closure states, branch success, or scientific completeness where the execution did not earn them.
Keep machine consequence below scientific authority.
Lean checks the conditional structure supplied to it.
It does not supply the empirical premises.
Troubleshooting and Failed-Proof Interpretation

When a requested proof or certificate is unavailable, diagnose the lowest layer that explains the failure.
Do not change the science merely because a Lean goal is inconvenient.
Do not strengthen Lean assumptions merely because the desired scientific conclusion is attractive.
The default diagnostic order is:
1. check the exact package and load identity;
2. check the record identity and scope;
3. check required burdens and their dispositions;
4. check scientific predecessor states;
5. check whether the requested theorem is actually the correct machine route for the scientific result;
6. only then treat the issue as a formalization defect.
The general rule is:
A blocked proof is evidence of a blocked proof until the scientific or semantic reason for that blockage has been established.
It is not automatically a failed experiment.
